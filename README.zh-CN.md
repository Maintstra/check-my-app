# Check My App（检查我的应用）

**一个"以证据为准"的 Agent Skill：像真实用户一样审查、修复并验收 Web、桌面、移动端和 AI Agent 产品。**

[English](README.md) · MIT 许可

编程 Agent 很会写代码，却不擅长回答"这个产品到底能不能用"。测试全绿，安装包却是坏的；设置向导走到死胡同；Agent 在结果未知时声称"付款成功"。Check My App 给你的 Agent（Codex、Claude Code 或任何读取 `SKILL.md` 的 Agent）一套严格、可重复的方法，诚实回答一个问题：

> **这个产品对真正要用它的人来说，准备好了吗？如果没有，具体要改什么？**

## 核心原则：没有证据，就不算通过

每条结论都必须标注：`confirmed`（有截图、操作记录、日志、权威回读或确定性测试支撑）、`inference`（从代码或文案推断，未在运行时观察到）、`untested`（未能测试，绝不悄悄算作通过）。阻断级问题不能被其他高分"平均掉"。

## 四种模式，权限明确

| 模式 | Agent 可以做什么 |
|---|---|
| **Audit 审查**（默认） | 只读检查与交互，不改文件、不产生外部影响 |
| **Fix & Retest 修复复测** | 只改授权范围内的本地文件，然后重跑失败的流程 |
| **Delivery Closure 交付收敛** | 盘点交付边界 → 修复 → 全量回归 → 循环直到收敛门槛通过 |
| **Release Gate 发布门禁** | 测试最终产物（安装包、线上版本），不得悄悄修补 |

"审查"不等于"可以修"；"修代码"也不等于可以发消息、写生产数据、购买或删除。

## 检查什么

- **真实用户体验**：从真实起点出发的有界流程，记录操作次数、耗时、死胡同、切换、反馈与恢复。
- **Agent 可信度**：证据、权限、中断、部分完成、过期状态、未知结果和对抗性请求。
- **安装后的真实情况**：语言完整性、真实数据形态、窗口尺寸与缩放、信息层级、桌面控件兜底。
- **可执行的问题单**：每条问题都有证据编号、用户影响、根因、具体改法、推荐与备选方案、取舍、严重度、工作量和精确复测方法。

## 示例

移动端只有源码/浏览器证据时，可参考[源码核对完成、设备交互未测的示例报告](examples/mobile-source-only/README.md)：不把未测计为通过。

## 输出

1. 符合 `check-my-app-report@1.1.0` 结构的 JSON 报告，附无依赖校验脚本（仅需 Python 3.10+ 标准库）。
2. 先给结论的人类摘要：**未就绪 / 可试点 / 可交付**。

## 安装

把 `skill/check-my-app` 文件夹复制到 `~/.codex/skills/`（Codex）或 `~/.claude/skills/`（Claude Code）即可；Windows 为 `%USERPROFILE%\.codex\skills\`。

## 使用示例

```text
用 check-my-app 审查这个 Web 应用"注册→开第一张发票"的流程，目标用户是第一次用的记账员。
用 check-my-app 的 Delivery Closure 模式，把这个桌面应用检查并修到可以交付；不要发邮件、不要写生产数据。
```
